Overview Course Report Architecture & URLs

1. Application Modules & Responsibilities

accounts

Models: Campus, User (AbstractUser)
Purpose: Authentication, institutional email validation, token generation, user profiles, and VerifiedRequiredMixin.

listings

Models: Category, Listing, ListingImage
Purpose: Marketplace catalog, condition categorization, multi-image upload formsets, search and price filtering.

messaging

Models: Conversation, Message
Purpose: Peer-to-peer campus communication, unique buyer-listing chats, and anti-self-messaging safeguards.

transactions

Models: Transaction
Purpose: Enforces the deal state machine (Requested → Agreed → Completed), inventory status syncing, and hand-off verification.

reviews

Models: Review
Purpose: Verified 1-to-5 star ratings, check constraints preventing self-review, and live non-denormalized rating calculation.

2. Relational Entity-Relationship (ER) Diagram

The relational schema enforces referral integrity, indexing on (campus, status, category), and unique constraints.

3. Transaction Lifecycle State Machine

Transitions are deterministic and validated at both model and controller levels.
